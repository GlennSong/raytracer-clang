The living city

Every person and car in a city is an agent: a small record with a home, a job, a role and a day, run by one deterministic simulation (CitySim). The idea that makes it scale is that an agent is simulated only as finely as anyone can see: in full near the player, coarsely further out, not at all beyond that, and drawn far away by a compute shader that only needs its route and the clock.

The older page How the City Thinks covers the early perception design (vision cones, signals, the first reactive walkers). This page is the system as it stands at commit 47d587f3: the day, the goals, the tiers, the scale work, transit, junctions and possession.

The problem

A procedural city is beautiful and empty. The roads, lots and buildings are generated, but nothing moves in them, and nothing has a reason to. The wish (ADR-0059, June 2026) was cars and pedestrians that use the generated roads, agents with a reason to move ("a daily schedule, home → work → home"), and later a city you can walk through at a real 1:1 clock and follow one person through their day.

Three things make that hard. Cost: the island level counts its walkers in the hundreds of thousands (ADR-0150 measured about 204,000) and has been pushed to 515,191 agents in all; nothing that touches every agent every frame survives that. Continuity: someone you turn away from must still be there, further along, when you turn back. Determinism: the engine's simulations replay from a seed (ADR-0002), so the same seed must give the same city, and identity, routing and parallel placement must not disturb the random-number stream.

An agent's day, as a flow

Everything an agent does comes from one chain. Its role (commuter, shopkeeper, student, waiter...) sets the parts of its day. The day is a goal table: a small state machine whose states either rest or go somewhere. When the clock, an arrival or a timer fires an event, the table picks the next state; a go state names a target (work, home, a café from a menu); the target becomes a node on the road graph; A* finds a route; and the agent moves along it at whatever level of detail its tier allows. Arriving fires the next event.

The chain behind every agent. Columns 1–4 are decided at transitions, which at the 1:1 clock happen minutes apart; column 5 runs every tick, at a cost set by distance from the player.

What an agent is

CitySim (src/apps/citysim/city_sim.h) owns one flat array of Agent structs and everything they share: the road graph, the places and venues, a goal table per role, the activity catalog, the bus network, the taxi dispatch, and spatial grids for neighbour queries. The ADR-0060 framing still holds: an agent is a brain (data); a car is an inert vehicle until an agent possesses it. A pedestrian is a brain with no car; a driver owns one (Agent::car) and is in it while driving (Agent::vehicle). mode says how it moves right now; archetype says what it is for the whole run, so a driver who parks and walks to a door doesn't switch to a pedestrian's day.

The main types. Solid arrows: what CitySim owns. Dashed: what an agent refers to by index (a node, a place id). The renderer, the walker bodies and the vehicle bridge live in separate systems (CityRenderSystem, CityWalkerSystem, CityVehicleSystem) and read the sim.

The tier field is the heart of the scaling story. Its comment is the best short description of the four levels of detail in the code:

Agent::Tier — K, V, D (and P, the physical overlay) src/apps/citysim/city_sim.h
    // Simulation tier (P4 three-tier traffic). K (Kinematic) is the full agent
    // as it always ran: sensing, FSM, signals, render bake, kinematic proxy.
    // V (Virtual) is a persistent FAR agent: full identity + exact route state
    // (link, lane, param, speed) but no rendering, no physics proxy, no
    // sensing/FSM and no live signal queries — it traverses its real A* route
    // on a coarse ~1 Hz tick at a modelled speed (class speed shaped by fixed
    // average junction delays), so promotion finds it where it should be.
    // P (the physical Jolt tier) stays what it was: possessTier's overlay on K.
    // Everything is K until a level opts in (CitySim::tieringEnabled) AND a
    // player position is fed (setTierCenter) — headless sims are unchanged.
    // D (Dormant) is the tier BELOW V: not simulated at all, not even coarsely.
    // A V agent still walks its route link by link once a second — cheap, but
    // not free, and there are thousands of them. A D agent costs nothing: when
    // the player comes near it is reconstructed from its own schedule
    // (scheduleSnapshot) and handed to V.
    //
    // Its CAR is untouched by any of this. Dormancy strips the agent, never the
    // vehicle — a parked car keeps its pose, its bay, its instance and its
    // proxy, which is what lets it still be seen, collided with and stolen
    // while its owner does not exist.
    enum class Tier : uint8_t { D, V, K };

The ground it walks on: NavGraph, places and identity

The NavGraph (src/engine/ai/nav_graph.h, ADR-0059) is the road network kept alive at runtime. The road builder used to sample every road into a fine polyline, stroke the asphalt, and throw the graph away; now the same graph survives as a directed lane graph. Each road edge becomes two NavLinks, one per direction (one for a one-way ramp), each a straight segment, so a curved street is a chain of short links. Traffic keeps left, UK/Japan style: the helper called rightOf in nav_graph.cpp is named for the maths and points to the driver's left.

NavLink: one direction of one road segment (excerpt) src/engine/ai/nav_graph.h
struct NavLink {
    int from = 0;                       // NavGraph node index (tail)
    int to = 0;                         // NavGraph node index (head)
    Real length = 0;                    // segment length (m)
    Real width = 8;                     // carriageway width of the source road (m)
    RoadClass klass = RoadClass::Local;
    int lanes = 1;                      // lanes available in THIS direction
    int layer = 0;                      // grade-separation level (0 = ground, >0 = bridge)

Further fields carry deck heights, one-way flags, access bits (walkable, frontage, signalable), the parking band, and whether the link is a footpath: park and quad walks are appended at load as walker-only links that vehicle routing never takes. Routing is one A*, shared by cars and walkers:

                bool onFoot = false,

The optional linkCostScale is how the bus planner spreads its routes: it charges extra for a street another route already drives.

Places (the second ADR-0066, "The Living City") give that graph somewhere to go. A Place is a typed building (home, shop, office, park, civic, and later cafés, bars, clubs, libraries, teaching halls) with a door snapped onto the pavement of its frontage street, hours, and a capacity. Generated buildings become places automatically (each shop front a place of its own), and assignPlaces gives every agent a home and a job it can actually reach. Since ADR-0150 homes and jobs are drawn in proportion to floor area, so a 30-storey block of flats houses more people than a bungalow. Identity is an AgentId: a dense UID handed out at build from a counter separate from the simulation's random stream, so adding identity changed no seeded test. Relationships (coworker, neighbour) are single tags on UID pairs, deliberately shallow.

A dead walkable graph. ADR-0066 Phase 2 built a separate pedestrian graph (ped_graph.{h,cpp}: corner nodes, sidewalk edges, a door node per place) so a walk could start and end at real doors. Its live integration was deferred, and walkers ended up routing on the NavGraph itself (findRoute(..., onFoot=true) plus footpath links and door positions). At 47d587f3, pedRoute has no caller outside its own test.

Roles: one system describes every resident's day

Glenn asked for "a singular system that can describe all of the npc roles" (2026-10-06). A role is data: the parts of a day — whether it commutes, how long before a break, what the break is, whether breaks repeat (class, break, class...), an errand on the way home, an evening menu and how often it goes out — plus, for a staff role, which places it staffs and on whose hours. Roles are authored in assets/scripts/roles.lua; the same catalog is built into C++ as defaultRoleCatalog, and a test keeps the two describing identically.

Staff and opening hours (ADR-0147). Staff come out of the existing population: each place of a staff role's kinds pulls its staff from the commuters living nearest it. A Venue then carries a 24-bit staffed mask — bit h set when someone hired there is at work at h:30 — and Venue::openAt requires the bit. Every customer chooser (outings, lunch, the evening, activities) asks openAt, so none of them needed changing. On island_8_nature that gates 2,585 shops, cafés, restaurants, bars and clubs: 1,315 staffed at 10:00, 742 at 22:00. Two kinds of place keep their posted hours anyway: one nobody was hired at, and one whose staff the schedule never has at work.

Goals as data: the GoalTable

Before ADR-0064 the day was a hand-written switch inside CitySim::step, and every new behaviour meant editing the simulation. Now it is a GoalTable (src/apps/citysim/city_goals.h): named states, each binding one action from a deliberately tiny C++ vocabulary — Rest or GoTo(target) — and transitions on a fixed set of events that the sim emits. The table rides the engine's generic StateMachine, so one table per archetype drives every agent; an agent holds only the int Agent::goal.

GoalState: one row of a day src/apps/citysim/city_goals.h
struct GoalState {
    std::string name;
    GoalAction action = GoalAction::Rest;
    GoalTarget target = GoalTarget::None;
    Activity activity = Activity::AtHome;
    double dwellHours = 0;   // 0 = rest forever (only events can end it)
    // GoalTarget::Activity: the spot kinds it takes (spotKindBit) and the tags the spot must carry (spot_tag) -- or,
    // when `menu` names one, a pick from that menu of the activity catalog (activities.h)
    uint32_t spotKinds = 0, spotTags = 0;
    std::string menu;
};

Targets cover more than home and work: Shop, Lunch, Outing, Campus, Activity (a menu pick), and the dynamic ones a taxi or bus table uses (Fare, Drop, Stop, Depot), looked up in the dispatch rather than stored on the agent — which is how one mechanism drives a resident, a cab and a bus. Firing an event is a lookup, then either a state change or a departure, gated so that the step's routing budget and a parked car's clearance are respected:

CitySim::tryGoalEvent: the table decides, C++ acts src/apps/citysim/city_sim.cpp
CitySim::GoalFire CitySim::tryGoalEvent(Agent& a, GoalEvent event) {
    const GoalTable& t = tableFor(a);
    int next = t.onEvent(a.goal, event);
    if (next < 0) return GoalFire::NoRow;
    const GoalState& to = t.state(next);
    if (to.action == GoalAction::GoTo) {
        int from = departNode(a);
        // ...
        if (a.archetype == Agent::Mode::Driver && !a.far() && !isBus(indexOf(a)) &&
            !launchClear(a, from))
            return GoalFire::Blocked;
        if (!isBus(indexOf(a)) && departuresThisStep_ >= kDeparturesPerStep)
            return GoalFire::Blocked;   // the step's routing budget is spent: leave next tick
        ++departuresThisStep_;
        a.goal = next;
        a.goalHours = 0;
        startGoalTrip(a, from, /*fromRest=*/true);
    } else {
        a.goal = next;
        a.goalHours = 0;
        a.activity = to.activity;
    }
    return GoalFire::Fired;
}

Load-time Lua, tick-time C++. agents.lua, roles.lua and activities.lua are read once at level load into these tables; nothing scripted runs in the tick. That keeps the tick deterministic and cheap, keeps the headless test build Lua-free, and turns a broken script into a loud load error. When the tables replaced the old switch, the built-in tables were checked to reproduce the old behaviour bit-exactly: an FNV hash over every agent's pose, speed, activity and trips across seven seeded scenarios, identical before and after, now pinned as installing_the_default_tables_changes_nothing.

Sleepers. An agent resting at a door has nothing to decide until its own day says so, so it names the sim-second it next needs thinking about (Agent::wakeAt) and drops out of the active list. Measured on metro v2 (2026-09-16), about 45% of near agents were asleep at any moment, and at 03:00 all of them — which is why a city can look static while working correctly.

Activities: what people go and do

A day's Outing, Lunch or evening is not hard-coded. It is a pick from a menu in the activity catalog (assets/scripts/activities.lua, mirrored by defaultActivityCatalog). An activity says what sites it uses (a café, a bench, a lawn, a pitch, "street"), when it is offered, how long it lasts, how far people will go for it, and how the body performs it (inside, outside, at a spot, wandering, or roaming in a group). A menu is a list of hour bands, each with "first" chances tried in order and then a weighted pick:

CitySim::pickFromMenu replaced three hand-written choosers (pickOuting, pickLunch, pickCampusBreak survive as one-line wrappers that name a menu). Group activities — a kickabout on the campus pitch, a chat circle or picnic on a lawn — are sessions: a definition with roles, a formation and a pose (stand, sit on the ground, lie), joined by whoever turns up, started when enough have, abandoned if not. CitySim::restPose is the one place both drawers (the instanced crowd and the near bodies) ask how a resting person stands, sits or lies.

Moving: reactive agents and the cognition loop

The first city sim (ADR-0060) moved agents by global plans: compute an A* route, snap along lanes leg by leg. That teleported at nodes and let agents drive through each other. ADR-0061 made agents reactive: each one perceives only what falls in a vision cone, runs a small state machine (walker: resting, walking, avoiding, waiting; driver: cruising, following, yielding, turning, waiting), and outputs a steering intent, not a jump. ADR-0063 then gave them an inner life between frames:

ADR-0063's five stages, each a small pure primitive in src/engine/ai/, composed inside CitySim. K-tier agents only: V and D agents neither sense nor decide.

TrackedBody and AgentMemory: sightings become tracks src/engine/ai/agent_memory.h
struct TrackedBody {
    int id = -1;          // the caller's stable body id
    Vec2 pos;             // best current estimate (extrapolated while unseen)
    Vec2 vel;             // smoothed velocity estimate (m/s)
    Vec2 seenPos;         // raw position at the last actual sighting
    Real lastSeen = 0;    // sim-time of that sighting
    Real confidence = 0;  // 1 = just seen, decays to 0 = forgotten
    bool hasVelocity = false;   // one sighting can't give a velocity yet
};

class AgentMemory {
public:
    Real memorySeconds = 4.0;    // unseen tracks survive (and extrapolate) this long
    Real velocityBlend = 0.5;    // EMA weight of the newest velocity estimate
    std::size_t maxTracks = 32;  // hard cap: weakest track evicted when full

Why memory matters: a car that saw a person step behind a van keeps expecting them where they were heading, and creeps to that spot instead of accelerating into it (pinned by cars_remember_a_person_after_losing_sight). Why a slow think cadence: walkers that re-decided every 100 ms visibly "wigged out"; deciding every 0.35 s (staggered per agent) and committing reads as intent. Controllers stay per tick for stability; decisions go slow for commitment.

Cars are deliberately not in each other's vision cones: lanes, car-following gaps and signals govern car-against-car, because braking for cross and oncoming cars in the cone deadlocked traffic. They do sense walkers, the player, and real physics vehicles (the player's car reaches the sim as an external obstacle with a half-length). Two cars that still meet on a closing course have a fender-bender: both freeze, then resume on staggered holds — they must collide, not ghost (cars_crash_and_stop_instead_of_ghosting).

Junctions

Junctions are where an agent sim earns or loses its credibility, and most of the city's hardest bugs lived here. The rules that stuck, in the order they were learned:

  • Stop lines that read as obeyed (ADR-0063): the line sits back by the junction box radius plus the zebra band plus half the car, so a car holding at red stands short of the crosswalk, not in the middle of it. Signals gained an all-red clearance so the box drains before cross traffic goes. ADR-0063 set green 12 s and all-red 2.5 s; the code now defaults to green 10 s, yellow 2 s, all-red 1.5 s and a walk phase of 8 s, because longer cycles queued more cars per red than small blocks hold (SignalController::build).
  • Don't block the box: no car crosses its line while a crossing car is inside; a turn waits for oncoming traffic, with agent order breaking the tie between two stopped opposing turners.
  • Knots and rings (ADR-0066): curvy generated crossings planarised into several nodes joined by car-length stubs, each node's box swallowing its neighbours' stop lines — a circular wait. Junction nodes within 7 m now merge, box radii are capped at 60% of the shortest arm, and a gridlock clock lets a car pinned 6–12 s stop yielding to stalled traffic and creep at 0.7 m/s. Worst all-stopped streak: 328 s → 9 s.
  • Think in route metres, not links. Metro's graph cuts streets into ~4 m links, so any rule written as "the current link" silently meant "4 m". Stop lines, signals and yields are found by junctionAhead along the route; car-following chains 60 m.
  • Promotion is a pile-up source. A far car drives blind, so handing it to the full sim at cruise put it 0.9 m behind a stopped queue. clearPromotion seats it behind the last body in its corridor at that body's pace, or leaves it far to try again.

Gates: metro_junctions_stay_clear (level tests; thresholds stuck < 300 car-seconds, overlaps < 800, from about 3,732 and 5,535 before the route-metre fixes) and city_phys_tier_packed_junction_does_not_pile_up (a physics soak).

Cars: one car system, two motion owners

ADR-0062 started from Glenn's requirement: "one car system". The player can walk up to any car and drive it, ejecting whoever was inside, and every car drives the same because every car is the same object. Whoever drives speaks only through one seam, a DriverInput {throttle, steer, brake, handBrake}, produced for AI by the pure computeDriverInput in src/engine/ai/driver_agent.h.

The first design made every ambient car a Jolt vehicle chasing a kinematic planner "ghost". Three device rounds of jammed junctions later, the ADR records a rethink: two clocks over one car (the planner's and the physics') meant every fix was another reconciliation loop — "the signature of a structural error, not a tuning problem". Pedestrians worked because their body was trivially commandable: one authority. So now there is one motion owner per regime:

"One car system survives where it matters — one component model, one fleet body, one enter flow, one physics API — while motion is owned per regime by the machinery that is good at it" (ADR-0062).

The vehicles page covers the bodies, the Jolt handling and the driver's seat.

Tiers of detail by distance

This is the second centrepiece: how a city of hundreds of thousands costs a few milliseconds. The rule from the measurements (below) is that cost is neighbour sensing in the near tier — position integration is nearly free — so the lever is how many agents are near, never the total. Every distance below is measured from the player (setTierCenter), with hysteresis between the in and out radii so agents on a boundary don't flap.

The bands, at their default radii (CitySim and CityRenderSystem fields). The upper block is how an agent is simulated; the lower is how a far one is still drawn.

Per-agent costs are from the scale bench (tests/test_sim_scale.cpp, 2026-09-16: 3.0 → 30.7 µs per near agent as density climbs; far ~0.3 µs). The pass that moves agents between tiers is short enough to read whole; this excerpt shows the adaptive ring and the V→K promotion:

CitySim::tierPass: the ring adapts, and promotion catches up first src/apps/citysim/city_sim.cpp
void CitySim::tierPass(Real hoursPerSecond) {
    if (!tieringEnabled || !haveTierCenter_) return;   // no player: all K
    const Vec2 c = tierCenter_;
    // the near target: ease the ring in when it holds too many, back out when too few (slowly: no pumping)
    if (nearTarget > 0) {
        const Real k = static_cast<Real>(kIdx_.size());
        if (k > nearTarget * 1.15) nearScale_ = std::max(Real(0.35), nearScale_ * 0.985);
        else if (k < nearTarget * 0.85) nearScale_ = std::min(Real(1.0), nearScale_ * 1.01);
    } else {
        nearScale_ = 1.0;
    }
    // ... the same for farTarget; K -> V past the demote radius; V -> D; D -> V on approach
    const Real reach = std::max(carPromoteRadius, pedPromoteRadius) * ns;
    // (V agents only, at their positions as of this tick's re-hash -- grid_'s too; a woken one was placed on waking)
    vGrid_.query(c, reach + 4.0, tierScratch_);
    for (int idx : tierScratch_) {
        Agent& a = agents_[static_cast<std::size_t>(idx)];
        if (a.tier != Agent::Tier::V) continue;
        const Real pr = (a.mode == Agent::Mode::Driver ? carPromoteRadius : pedPromoteRadius) * ns;
        const Real dx = a.pos.x - c.x, dy = a.pos.y - c.y;
        if (dx * dx + dy * dy >= pr * pr) continue;
        // Catch the V state up to NOW, then hand it to K exactly where the
        // catch-up left it: the promotion pose IS the lane pose — no teleport,
        // no snap. Render + kinematic proxy pick it up on this step's bake.
        tickV(idx, hoursPerSecond);
        if (!clearPromotion(idx)) continue;   // no room behind: stays far, retries
        setTier(idx, Agent::Tier::K);
        grid_.place(idx, a.pos);
        ++promotions_;
    }

Some agents never go dormant: anyone driven by the player or tethered to a body, anyone pinned (being followed: "I'd definitely want it so I could follow someone around the city"), anyone remembered (near you in the last 10 minutes, so turning around doesn't make them vanish), and every bus and bus rider — freezing buses out past the bubble once stranded every rider waiting along a loop.

Dormant agents keep their day

A D agent costs nothing per tick, but the city it belongs to keeps time. Each dormant agent has one entry in a min-heap keyed on the game clock: its next departure or arrival (from its schedule, its evening plan, or noon, when tonight's plan is drawn), or — while travelling — a waypoint every 4 s (kDormantWaypointSeconds, ADR-0150) so through traffic is where it should be when it wakes. Each tick pops what is due:

CitySim::runDormantEvents (excerpt) src/apps/citysim/city_sim.cpp
void CitySim::runDormantEvents() {
    static const bool off = std::getenv("RT_NO_DORMANT_EVENTS") != nullptr;   // A/B: sleepers frozen, as before
    if (off) return;
    // ...
    int budget = 400;   // a backlog (a long pause, a clock jump) spreads over ticks instead of a hitch
    while (!dormantHeap_.empty() && budget > 0 && dormantHeap_.top().at <= clockTotalHours_) {
        const DormantEvent ev = dormantHeap_.top();
        dormantHeap_.pop();
        const std::size_t i = static_cast<std::size_t>(ev.agent);
        if (i >= agents_.size() || i >= dormantEventAt_.size() || dormantEventAt_[i] != ev.at) continue;   // stale
        Agent& a = agents_[i];
        if (a.tier != Agent::Tier::D) { dormantEventAt_[i] = -1.0; continue; }
        --budget;
        // ... a waypoint on the way: dormantGlide along the route, re-push, continue
        placeFromSchedule(ev.agent);
        a.vLastTick = simSeconds_;   // its pose is of now (the crowd's t0, a wake's resume)
        grid_.place(ev.agent, a.pos);
        dGrid_.place(ev.agent, a.pos);
        crowdChanged(ev.agent);
        ++dormantEventsRun_;
        scheduleDormantEvent(ev.agent);
    }
}

Stale entries are skipped by comparing the event's time with the agent's current one, rather than deleting from the heap. When the player comes near, wakeDormant rebuilds the agent from scheduleSnapshot (at work, at home, on the way, at tonight's venue...) and hands it to V — never straight to K, because waking is an approximation and V is the tier whose job is being approximate. A dormant agent mid-trip instead resumes where the clock says it is: where the GPU crowd has been drawing it.

The GPU crowd

Far agents still need to be seen. shaders/vulkan/crowd.comp runs one invocation per far traveller (V or D, on a trip). Where it is now is a pure function of the clock: its distance at t0 plus speed times the time since, found on its route by binary search over running distances. The shader culls by distance and the view planes and appends an instance to its kind's indirect draw with an atomic. The CPU never touches a far person per frame; it only rewrites a 32-byte record when a far trip changes (CitySim::takeCrowdChanges).

crowd.comp: a far traveller is a route, a distance and a clock shaders/vulkan/crowd.comp
struct Agent {
    uint routeOff;   // first entry in Routes
    uint routeLen;   // entries
    float dist0;     // metres along the route (from its first entry's link start) at t0
    float t0;        // sim seconds
    float speed;     // m/s
    float side;      // metres off the link's centreline, to its right (x = dir.y, z = -dir.x)
    uint kind;       // which mesh / material (Kinds, Cmds)
    uint live;
};

Stand-ins are not drawn closer than 120 m (cars) or 60 m (walkers): up close is the full sim's job, and a far car waiting on promotion once drew as a box in the lane at 10 m. RT_NO_GPU_CROWD=1 turns it off; on renderers without it (supportsGpuCrowd() false: Metal, WebGPU), a CPU band draws far agents instead.

Transit: buses, cabs and trains

A bus is an agent with a one-state table ("drive the loop, for ever") and a BusNetwork (city_bus.h) of derived loops: farthest-point hubs, legs A*'d street-only with a reuse price so routes spread, stops 180–300 m apart, and every loop given a reverse twin so buses run both ways. The metric that mattered was not distance coverage (94% within 220 m hid the problem) but the share of streets a bus drives: 28% → 58%. Buses dwell 10 s plus 3 s a rider; with a depot they have a service day (05:30–23:30) and sleep in their bays overnight.

Riders choose with planTrip: door-to-door time (walk, half the headway as the wait, the ride round the loop, one transfer within 100 m), taken only if it beats walking by max(60 s, 15%). Under the old walk-only rule 58% of accepted trips were slower than walking. Between towns there is no walk to beat (walkable=false); that one change took island bus commuters from 34 to 602 of 948. Cabs are drivers with a taxi table matched by Dispatch; trains are a separate RailSim whose riders (ADR-0156) walk to platforms the same way. The player rides a bus in the bus's own frame, placed through its drawn matrix.

Possession: every drawn agent is two objects

Possession lets a director — a script, a model, the player — run one agent. The control channel (ADR-0078/0079) takes verbs like possess, walk_to, direct on, agent? and release; tools/citywalk.py drives them. Building it turned up the fact anyone working here needs first (ADR-0091 amendment):

"A director that moves the plan without moving the body has not moved the agent" (ADR-0091).

stepTick: the plan waits for its body src/apps/citysim/city_sim.cpp
        // Tethered ghost too far from its physical car: WAIT for it. The plan can
        // never outrun the physics — a car knocked back, climbing, or slow off the
        // line finds its ghost holding just ahead instead of gone (ADR-0062).
        if (a.moving && a.tethered) {
            Real dx = a.pos.x - a.tetherAnchor.x, dy = a.pos.y - a.tetherAnchor.y;
            if (std::sqrt(dx * dx + dy * dy) > a.tetherLead) {
                a.speed = 0;
                a.state = Agent::State::Waiting;
                ++tetherHeldThisTick;
                continue;

The frozen-agent bugs this explained were each "individually reasonable" layers: a destination snapped to an unroutable node, a no-path branch that parked the agent, the goal layer re-planning from the rest node (moving the ghost 27–290 m), and the leash then holding it. sendAgentTo now validates a route before touching the agent. The agent? verb reports stepped (did advance() run), anchorDist and lead, which diagnose a frozen agent in one poll; and direct on holds the goal layer off so the schedule stops fighting the director.

The decision service and Laya

ADR-0091 proposed one agent that decides for itself: a decision service consulted only at transitions (minutes apart at a 1:1 clock), offered a menu the engine built from what is legal right now, answering asynchronously with the scripted table as fallback, and logging every (state, menu, choice, latency) as replay trace and training data. A local LLM via Ollama was rejected (measured 18–33 s a call). What exists at 47d587f3 is the director half: tools/citywalk.py possesses a walker, builds a menu of nearby places from look?, asks a pluggable decider, walks there, and logs. The deciders are a stub (nearest unvisited) and Laya, an open-weights 421M-parameter encoder that answers choice / score / "how likely is this true" questions with a probability per option, run on the CPU at about 450 ms a call so the GPU stays with the renderer:

citywalk.py: the menu goes to Laya as a choice question tools/citywalk.py
    def decide(state, menu):
        keys, criteria = [], {}
        for i, c in enumerate(menu):
            k = f"{i}_{re.sub(r'[^a-z0-9]+', '_', str(c['what']).lower()).strip('_')}"[:40]
            keys.append(k)
            criteria[k] = c["label"]
        questions = {
            "where_next": {"type": "choice",
                           "instructions": "Where should this person go next?",
                           "criteria": criteria},
            "in_a_hurry": {"type": "noul",
                           "instructions": "This person is in a hurry."},
        }
        t0 = time.time()
        res = agent.predict(describe(state), questions)
        ms = (time.time() - t0) * 1000
        ans = res["answers"]["where_next"]
        pick = ans.get("choice")
        idx = keys.index(pick) if pick in keys else 0

Because the engine builds the menu, an out-of-range answer is impossible. In its first live run (2026-09-21) Laya chose a civic building 85 m away, stuck with it across three decisions until it arrived, then picked a park. The in-engine half — a sidecar consulted at goal-table transitions — is not built.

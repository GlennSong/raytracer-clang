Control verbs

A running viewer listens on a local socket, and anything that can write a line of text can drive it: a probe script, Claude through the MCP server, or you with nc. These are all 85 things it can be told, straight from the engine's command table, where every verb is registered once with its usage and what it does.

85verbs in all
38questions (ending in ?)
32act directly
28send a typed request
24answered by their system

How a line gets in

One line in, one line out. The socket thread never touches the engine; every verb runs on the main thread, where the world, the renderer and Settings are safe to touch (ADR-0072's staging rule).

What a verb looks like

The teleport verb: its name, usage and summary, then the handler src/engine/application_commands.cpp
commandTable.add("teleport", "teleport <x y z [pitch yaw] | x z>",
                 "Move the player (the camera when there is none); `x z` lands on the ground. Read the result with teleport?.",
                 [this](const ControlCommand& cmd) -> std::string {
    // Move the PLAYER (the camera when there is none): "x y z [pitch yaw]"
    // or "x z" (on the ground) — the Teleport panel's paste format, so a
    // location goes between the panel, the log and a session by paste.
    // A TeleportRequest for TeleportSystem; `teleport?` (bound by it) answers.
    if (cmd.args.empty()) return "err usage: teleport <x y z [pitch yaw] | x z>";
    std::string pose = cmd.args[0];
    for (size_t i = 1; i < cmd.args.size(); ++i) pose += " " + cmd.args[i];
    TeleportRequest r;
    if (parseTeleportPose(pose, r.pose) < 2) return "err unreadable pose: " + pose;
    return publishRequest(eventBus, r, "teleport", "ok teleport staged (poll `teleport?`)");
});

Registering a name a second time is refused and logged, so one verb can never have two handlers. That is how ride went wrong in the old if-chain: it was handled twice and the second handler never ran.

Try it

From a terminal, with a viewer running
printf 'commands?\n' | nc -U /tmp/raytracer-viewer-*.sock
printf 'teleport 20 600\n' | nc -U /tmp/raytracer-viewer-*.sock
printf 'teleport?\n' | nc -U /tmp/raytracer-viewer-*.sock

A Claude session in the repo gets the same verbs as tools through tools/viewer-mcp.py (docs/control-channel.md).

Where it is going

The last column shows how each verb reaches the system that does the work. Most used to go through the Settings string bus: the verb wrote a named Settings key that a system checked every frame, or read a string a system kept rewriting. ADR-0253 retired it, with the text on the wire unchanged. Now a command acts directly or sends a typed request on the EventBus, which the system that does the job hears (with no such system in this state, the verb says so), and a question is answered by its system while that system runs. The same requests are named events: events? lists them, publish sends one, watch streams them as they happen, and Lua scripts can send and hear them too, or add verbs of their own. The MCP server builds its tools from this same list.
